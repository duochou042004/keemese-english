# ADR-0006: TanStack Router

Status: Accepted (2026-10-17)

## Context
We evaluated React Router and TanStack Router against what the app actually needs:

| Need | Where it shows up |
|---|---|
| Lots of filtered lists whose state belongs in the URL (shareable, survives reload) | Library (folder, kind, tag, query), question bank (type, tag, difficulty), review queue, calendar (view, date) |
| Two role areas with different guards and lazy bundles | `/t/*` tutor, `/s/*` student |
| Data loading that cooperates with TanStack Query | Every page |
| Type safety on links and params across ~40 routes | Prevents broken links during refactors |

Versions checked 2026-10-17: `react-router` 8.4.0, `@tanstack/react-router` 1.170.x.

## Decision
**TanStack Router**, file-based routes via its official Vite plugin, with `validateSearch` schemas written in Zod for every route that has search params. Route loaders call `queryClient.ensureQueryData` so router and TanStack Query share one cache.

## Why not React Router
React Router can do all of this, but search params arrive as untyped strings and need hand-written parsing on every list page. It has also shipped three majors (v6 → v7 → v8) in about three years, which is a churn risk for a long-lived app with AI-assisted maintenance. TanStack Router has stayed on v1 with typed search params as a core feature.

## Consequences
- A generated `routeTree.gen.ts` (committed, regenerated by the Vite plugin).
- Contributors and agents must follow its file-naming conventions ([frontend IA](../frontend/information-architecture.md#routes)).
- **We do not switch routers later without evidence and a superseding ADR.**

## Revisit when
TanStack Router is abandoned, or a hard incompatibility with React 19+ or Vite appears.
