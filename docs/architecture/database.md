# Database Design (PostgreSQL 18)

This is the target logical schema. **EF Core migrations are the source of truth once they exist.** Update this file in the same PR as any migration.

## Conventions

- `snake_case` names (Npgsql `UseSnakeCaseNamingConvention` or explicit configuration). All in the `public` schema.
- PK `id uuid` (UUID v7, generated by the app). FKs end in `_id`. Every FK column has an index.
- Audit: every table has `created_at timestamptz not null` and `updated_at timestamptz not null`, set by an interceptor. Append-only tables (`metric_readings`, `audit_events`) have `created_at` only.
- Enums are stored as `text` with a `CHECK` constraint, never as PostgreSQL enum types (easier migrations).
- Concurrency: the `xmin` system column is mapped as the row version on the aggregates the tutor edits (`activities`, `lessons`, `lesson_sessions`, `learning_plans`, `questions`, `content_items`, `student_profiles`).
- Extensions: `unaccent` (search). `citext` is not used; case-insensitivity comes from `lower()` indexes.
- Search: `f_unaccent(lower(col)) LIKE f_unaccent(lower('%' || q || '%'))`, where `f_unaccent` is an `IMMUTABLE` wrapper defined in the first migration. Add a trigram index only if NFR-PERF-01 needs one.

## Soft delete and retention policy

| Kind | Rule |
|---|---|
| Library items (`content_items`, `questions`, `activities`, `lessons`) | `archived_at timestamptz null`. Archived items are hidden from pickers and lists by default but keep working in history. Hard delete is allowed only when unreferenced (FK `RESTRICT`) |
| Students | Archive = `users.is_active = false`. **Permanent delete** cascades to all student-scoped rows, and the app deletes their stored files in the same request (files are removed after the DB commit; a failed file delete is logged and retried on the next start) |
| Notes, goals, metrics, plan items, sessions | Hard delete (with UI confirmation). No restore |
| `audit_events` | Kept 1 year, then pruned on startup (lazy, no scheduler) |

No global EF query filters, because archived items must stay visible in history. Each list query filters explicitly.

## Security-sensitive columns

| Column | Handling |
|---|---|
| `users.password_hash`, `security_stamp` | Identity PBKDF2 hashing. Never serialized to DTOs. Never logged |
| Temporary passwords | Never stored. Generated, hashed, returned once in the reset or create response |
| `teacher_notes.body`, `lesson_sessions.prep_notes` | Tutor-only DTOs. The isolation suite asserts their absence from `/api/me/**` |
| `student_activities.snapshot` (answer keys), `questions.payload` | Redacted for students before release ([activity engine](../backend/activity-engine.md#redaction)) |
| `student_profiles.phone`, `contact_channels`, `parents` | Personal data. Tutor-only. Removed on permanent delete |
| `audit_events.ip_hash` | SHA-256 of IP + a per-install salt, never a raw IP |

## File metadata

`stored_files` is the only place file facts live. `original_name` is used for the `Content-Disposition` download name (RFC 6266 `filename*` encoding for Vietnamese names) and is never used as a path. Files are referenced by `content_items`, `question_files` and `answer_files`. Orphans (uploaded but never attached within 24 hours) are deleted lazily on the next upload by the same user.

## Migrations

- `dotnet ef migrations add <Name> --project src/Keemese.Api`. One migration per PR, named after the feature.
- Migrations must be reversible where practical. Destructive migrations (dropping or narrowing a column) need a note in the PR and the release notes.
- CI applies all migrations to an empty database during the integration tests.
